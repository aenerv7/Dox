# Dox Reader Backend

部署在自己 Cloudflare 账号中的个人 RSS 服务。Dox Reader 前端通过后端地址和访问令牌连接，服务端在所有客户端关闭时仍定时抓取。

## 部署

要求 Node.js 24+、npm 11+ 和 Cloudflare Workers Free 账号。每位用户独立部署，不使用公共后端。

```powershell
npm ci
npm run check
npx wrangler login
npx wrangler deploy
npx wrangler secret put BACKEND_TOKEN
```

最后一步输入自己生成的随机令牌（至少 32 字符，推荐 32 随机字节的十六进制字符串），不要把令牌写进源码或命令行。配置令牌前 API 拒绝所有数据请求。

在 Firefox 扩展或网页版的设置中选择「自建后端」，填入部署输出的 HTTPS 根地址和访问令牌，等待自动读取后端设置，调整抓取间隔和保留篇数后保存。

## 默认与范围

- 默认每 60 分钟抓取，支持 30–10080 分钟；手动刷新最短间隔 1 分钟。刷新由后端异步执行，关闭客户端不会取消任务。
- 全部订阅合计保留按发布时间排序的最新 10000 篇，支持 100–10000；相同发布时间以文章 ID 排序。收藏和未读也计入并受此上限约束。调低上限立即清理旧文章。
- 最大 100 个订阅源。RSS/Atom 响应上限 5 MiB，每次唤醒抓取一个源，90 秒超时，失败指数退避。抓取请求使用固定、非个人化的 Dox Reader 标识，兼容会拒绝空 `User-Agent` 的旧站点。
- 不抓原网页全文或保存图片；保存订阅源提供的正文，超过约 48 KiB 的正文保留节选并提示打开原文。
- 另设 600 MiB 正文及元数据预算；每日最多 4800 次抓取，以及保守的写入预算（每条新文章占 4 单位、状态更新占 1 单位，共 10000 单位）。额度不足顺延到次日 UTC，已有数据保留。
- 使用 SQLite Durable Objects 与一个每小时恢复检查的 Cron，不要求 D1、R2、Queues 或付费套餐。上述应用预算留有余量，但不能抵消同账号其他应用的使用或任意外部流量；Cloudflare 免费额度耗尽时服务会报错，应用不会自动升级套餐。

本地模式与后端数据互相独立。可先在本地模式导出 OPML，再切换后端模式导入；文章历史不会自动上传。后端模式下已读、收藏和订阅由服务器管理，外观偏好保存在当前设备。WebDAV 仅用于本地模式。

每个后端地址在浏览器拥有独立缓存。离线时可以查看已缓存的列表和打开过的正文；修改状态需要连接后端。清除本机缓存不会删除远端文章。

## 本地验证

在被忽略的 `.dev.vars` 中设置 `BACKEND_TOKEN`，运行 `npm run dev`。测试使用独立的本地 Workers runtime 和模拟订阅，不访问生产账号。

`npm run check` 包含类型检查和 Workers 集成测试。部署预检：`npx wrangler deploy --dry-run`。
